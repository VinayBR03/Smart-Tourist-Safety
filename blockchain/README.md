# ⛓️ Blockchain — Sentinel Tour

Tamper-proof audit ledger layer for the Sentinel Tour platform. Six Solidity smart contracts record every critical state change — incidents, zone risk levels, assignments, evidence uploads, health alerts, and admin actions — on an immutable append-only chain. The backend calls these contracts directly via `web3.py` (`blockchain_service.py`).

> **Design:** These are **audit ledgers**, not identity or access-control contracts. No NFTs, no role gates — pure append-only event logs with `bytes32` data hashes for integrity verification.

## 📜 Smart Contracts

All six contracts follow the same pattern: **append-only array, emit event, expose `getRecord(index)` and `total()`**. No upgradability, no access control — intentionally simple for auditability.

### `IncidentLedger.sol`

Logs every incident status transition.

```solidity
function logStatusChange(
    uint256 incidentId,
    string  oldStatus,
    string  newStatus,
    uint256 changedBy,
    bytes32 dataHash       // SHA-256 of full incident payload
) external
```

Event: `IncidentStatusChanged(incidentId, oldStatus, newStatus, changedBy, timestamp, dataHash)`

---

### `ZoneLedger.sol`

Logs zone risk level changes with score and source.

```solidity
function logRiskChange(
    uint256 zoneId,
    string  oldRiskLevel,
    string  newRiskLevel,
    uint256 riskScore,     // score × 100  (e.g. 0.75 → 75)
    string  source,        // "ml_engine" | "manual" | "incident"
    bytes32 dataHash
) external
```

Event: `ZoneRiskChanged(zoneId, oldRiskLevel, newRiskLevel, riskScore, source, timestamp, dataHash)`

---

### `AuditLedger.sol`

General-purpose audit trail for any user action on any entity.

```solidity
function logAction(
    uint256 userId,
    string  action,        // e.g. "CREATE_INCIDENT", "UPDATE_ZONE"
    string  entityType,    // e.g. "Incident", "Zone", "User"
    uint256 entityId,
    bytes32 dataHash
) external
```

Event: `AuditLogged(userId, action, entityType, entityId, timestamp, dataHash)`

---

### `AssignmentLedger.sol`

Logs who assigned which incident to whom and when.

```solidity
function logAssignment(
    uint256 incidentId,
    uint256 assignedTo,
    uint256 assignedBy,
    string  action,        // "ASSIGNED" | "REASSIGNED" | "UNASSIGNED"
    bytes32 dataHash
) external
```

Event: `AssignmentChanged(incidentId, assignedTo, assignedBy, action, timestamp, dataHash)`

---

### `HealthAlertLedger.sol`

Logs critical health anomalies from IoT wristbands.

```solidity
function logAlert(
    uint256 touristId,
    uint256 deviceId,
    string  alertType,          // "HIGH_HEART_RATE" | "LOW_SPO2" | "SOS" etc.
    uint256 heartRate,
    uint256 spo2,
    uint256 bodyTemperature,    // × 100  (e.g. 36.5°C → 3650)
    bytes32 dataHash
) external
```

Event: `HealthAlertTriggered(touristId, deviceId, alertType, heartRate, spo2, bodyTemperature, timestamp, dataHash)`

---

### `EvidenceLedger.sol`

Logs media evidence (photos/videos) uploaded to an incident.

```solidity
function logEvidence(
    uint256 incidentId,
    uint256 uploadedBy,
    string  mediaType,     // "image" | "video" | "audio"
    string  storageKey,    // S3 object key
    bytes32 fileHash,      // SHA-256 of the actual file bytes
    bytes32 dataHash
) external
```

Event: `EvidenceLogged(incidentId, uploadedBy, mediaType, storageKey, fileHash, timestamp, dataHash)`

## ⚙️ Setup

### Prerequisites

- Node.js 18+
- npm

```bash
cd blockchain
npm install
```

### Compile

```bash
npx hardhat compile
# Output → artifacts/
```

### Start Local Node

```bash
npx hardhat node
# Runs at http://127.0.0.1:8545
```

### Deploy All 6 Contracts

```bash
npx hardhat run scripts/deploy.ts --network localhost
```

## 🔗 Backend Integration

`blockchain_service.py` uses `web3.py` to call contracts. Blockchain failures **never break backend flow** — errors are caught and returned as a string, and the `tx_hash` is stored in the `blockchain_tx_hash` DB column:

| Backend Call | Contract |
| ------------- | --------- |
| `log_incident_status(id, old, new, by)` | `IncidentLedger.logStatusChange` |
| `log_zone_risk(id, old, new, score, source)` | `ZoneLedger.logRiskChange` |
| `log_audit(user_id, action, entity_type, entity_id)` | `AuditLedger.logAction` |
| `log_assignment(incident_id, to, by, action)` | `AssignmentLedger.logAssignment` |
| `log_health_alert(tourist_id, device_id, type, hr, spo2, temp)` | `HealthAlertLedger.logAlert` |
| `log_evidence(incident_id, by, media_type, key, file_hash)` | `EvidenceLedger.logEvidence` |

## 🔐 Security Notes

- Deploy script uses Hardhat's default dev key `0xac0974bec39a...` — **replace for any non-local deployment**
- All sensitive data stays off-chain; only SHA-256 hashes go on-chain
- Contracts have no access control — add OpenZeppelin `AccessControl` before mainnet deployment
- `deployed_addresses.json` is safe to commit (addresses, not keys)
